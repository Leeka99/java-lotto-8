# 🎰로또

---
## 👨‍🏫프로젝트 소개
> 간단한 로또 발매기를 구현하는 프로젝트입니다. <br>
> 사용자가 구입 금액을 입력하면 그 금액에 맞게 로또를 자동 생성하고,
> 당첨 번호와 보너스 번호 입력 후 당첨 내역과 수익률을 계산해서 보여줍니다.
> 
>> #### 🕹️주요기능
>> - 사용자가 로또 구입 금액 입력
>> - 구입 금액에 맞게 로또 번호 자동 생성
>> - 사용자가 당첨 번호 6개 입력
>> - 사용자가 보너스 번호 1개 입력
>> - 로또 당첨 내역 및 수익률 계산 및 출력
>> - 입력값 예외처리

## 📝테스트 코드를 작성하는 이유 정리
> 테스트코드를 작성하며 `얻었던 것`, `유용했던 점`, `내가 생각하는 테스트코드란?`에 대해서 작성했습니다.
>
> ### 1. 클래스 분리의 필요성 & 책임 분리
>> - 테스트 코드를 작성하면서, 하나의 클래스나 메서드가 너무 많은 기능을 담당하고 있다는 문제를 발견했습니다. <br> 
>> - 특정 기능을 테스트하려고 할 때 필요 없는 매개변수가 계속 들어가는 것을 보고, 클래스와 메서드를 작고 단일한 책임만 가지도록 분리했습니다. <br>
>> - 이를 통해 테스트가 간단 명료해졌으며, 각 클래스와 메서드의 역할이 명확해졌습니다.
> 
> ### 2. 생각해보지 못한 에러 발견
>> - 테스트 하기 쉬운 코드로 리팩토링하니 여러 조건을 편하게 검사할 수 있었고, 기존에는 생각해보지 못했던 값에 대해서도 테스트 할 수 있었습니다.
>> - 그 결과, 기존 코드의 문제점을 발견했습니다.
>> - 대표적으로 `로또 당첨 개수 * 상금` 계산 과정에서 엄청 큰 값(200억)이 int로 계산된 후 오버플로우 된 상태에서 double로 바뀌는 이슈를 확인했습니다.
>
> ### 3. 기능 검증
>> - 테스트 코드는 다른 사람들에게 내가 작성한 코드가 올바르게 동작한다는 것을 증명하는 <b>문서 역할</b>을 한다고 생각합니다. <br>
>> - 기본값 검증뿐 아니라 추가적인 예외 테스트까지 모두 진행했음을 보여주어, 별도의 설명 없이도 코드의 안정성을 확인할 수 있습니다.
>
> ### 4. 구현해야 할 기능 체크
>> - 테스트를 진행하면서, 계획한 모든 기능이 제대로 구현되어 있는지 한 번 더 검증할 수 있었습니다.
>
> ### 5. 학습자의 입장에서 깊은 생각을 해볼 수 있다.
>> - 테스트 코드를 작성하며 인터페이스 활용, 생성자 오버로딩, 캡슐화 등 다양한 기법을 리팩토링 과정에서 응용했습니다. <br>
>> - 어떻게 하면 정상적인 테스트를 만들까? 와 어떻게 하면 좀 더 편하게 테스트할까? 를 고민하며 코드를 개선했습니다. <br>
>> - 그 결과, 처음보다 훨씬 책임이 명확하고 가독성이 높은 코드를 완성할 수 있었습니다.

## 🤔신경 쓴 부분 & 고민했던 부분
> ### 1. Input에서 Integer로 변환해서 넘겨줘야할까? 각 클래스의 책임 범위
>> - 사용자에게 입력받은 값은 처음에는 문자열(String) 형태이므로, 이를 숫자(Integer)로 변환하는 책임을 어디에 둘지 고민했습니다. <br>
>> - 문자열을 검증하는 클래스에서 변환까지 담당하는 것이 적절하다고 생각했습니다. <br>
>> - 문자열 검증을 통과했다는 것은 문자열로 받은 입력값에 대해서는 문제가 없다는 것이기에 이후 기능에서 검증된 값을 바로 사용할 수 있는 형태로 넘겨주는 것이 자연스럽다고 생각했습니다. 
>
> ### 2. 클래스명.변수 vs this.변수
>> - 처음에는 this.를 사용하면 무조건 필드변수를 참조한다고 생각했습니다. <br>
>> - 물론 실제로 사용가능지만, 정적(static) 필드에 this.를 붙이면 노랑 경고줄이 발생합니다. <br>
>> - this.를 사용하더라도 내부적으로 `클래스명.필드` 형태로 접근해서 호출한다고 합니다. <br>
>> - 따라서 정적 필드를 참조할 때는 this. 대신 `클래스명.필드`로 접근하는 것이 명확하다고 판단했습니다.
>
> ### 3. 올바른 입력값을 받을 때까지 반복하기
>> - 어떻게 원하는 지점부터 입력을 다시 받을 수 있을까? 에 대한 고민이었습니다.
>> - 이를 위해 while문과 try-catch를 활용했습니다. <br>
>> - try 블록 안에 break를 두어 만약 값이 정상적으로 처리되었다면 while문을 벗어나 다음 입력을 처리하도록 했습니다. <br>
>> - 만약 예외가 발생하면 catch 블록에서 에러 메세지를 발생시키고 while문을 통해 무한 반복되도록 구현했습니다.
>> 
> 
> ### 4. 예외처리 클래스도 분리해서 만들어보자
>> - `IllegalArgumentException`을 상속받는 커스텀 예외처리 클래스를 만들어 활용했습니다. <br>
>> - 이렇게 분리하니 코드 내에서도 예외가 발생하는 이유를 명확하게 구분할 수 있었고, 유지보수가 훨씬 쉬워졌다고 생각합니다.
>
> ### 5. enum 사용하기. 어디에 사용해야할까
>> - 처음에는 많이 생소한 개념이었습니다. 하지만 많이 유용했습니다.<br>
>> - `상금에 관한 상수`, `예외처리 문구`, `자주 사용하는 값`을 enum으로 관리했습니다. <br>
>> - enum이 제공하는 ordinal(), values() 메서드, 그리고 get 메서드를 만들어 활용할 수 있었습니다. <br> 
>> - 덕분에 코드의 가독성이 크게 올랐고, 상수 관리가 단순하고 명확해졌습니다.
>
> ### 6. 값을 하드코딩하지말자
>> - 코드를 살펴보니 값이 변하면 여러군데서 코드가 망가지는 대참사가 일어나기 직전이었습니다. <br>
>> - 상수를 enum 클래스로 나누어 관리해주었습니다.
>
> ### 7. 테스트를 위해 생성자를 만들자
>> - 테스트를 진행하는데 필요하지 않은 매개변수까지 매번 넣어줘야했습니다. <br>
>> - 테스트 때 필요한 매개변수만 입력받을 수 있는 생성자를 만드는것이 좋지 않을까?라는 생각을 했습니다. <br>
>> - 따라서 생성자 오버로딩을 통해 테스트용 생성자를 별도로 만들어, 테스트 코드의 효율성을 높였습니다. 
>
> ### 8. 작은 단위로 테스트하기 & 클래스가 담당한 기능을 조금 더 분리해보자.
>> - CalculateWinning 클래스가 전체 계산 기능을 담당하고 있었습니다. <br>
>> - 하지만 테스트를 진행하면서, 하나의 클래스 안에 여러 계산 로직이 혼합되어 있는 문제를 발견했습니다. <br>
>> - 그래서 `상금 총합 계산`, `수익률 계산`, `문자열 포맷팅 기능`을 각각의 클래스로 분리해습니다.
>> - 그 결과, 테스트 단위가 명확해지고, 테스트 클래스 이름만 보고도 어떤 테스트인지 쉽게 파악이 가능해졌습니다.
> 
> ### 9. static 변수 vs 인스턴스 변수
>> - 개별 테스트는 모두 통과되었지만, 전체 테스트를 실행하면 일부가 실패했습니다. <br>
>> - 인스턴스 변수로 모두 바꿔줘야할까 `reset()` 메서드를 만들어 `@ BeforeEach`로 돌려줘야할까에 대한 고민을 했습니다.
>> - 현재 프로그램은 1명의 사용자에 대해서 1회성으로 실행되므로, `static`으로 선언하는 것이 적절하다고 판단했습니다.
>> - 따라서 필드를 초기화해주는 `reset()` 메서드를 작성하고, `@ BeforeEach`를 통해 매 테스트마다 값을 초기화하도록 구현했습니다.
>
> ### 10. 한번 더 깨달은 자바 API의 위대함
>> - 금액을 원 단위로 표시하기 위해 고민했습니다. <br>
>> - 두 가지 방법을 생각했습니다. <br>
>>   1. 두 개의 String을 만들어 뒤에서부터 세 글자씩 끊어 처리하는 방법 <br>
>>   2. 뒤에서 한 글자씩 출력하며 3번째마다 쉼표를 찍는 방식 <br>
>> - `첫 번째 방법`은 String이 불변객체라 메모리 낭비가 발생할 수 있다고 판단했습니다. <br>
>> - `두 번째 방법`은 코드가 지나치게 비효율적으로 보였습니다. <br>
>> - 뒤늦게 자바 API를 찾아보았고 `String.format()`이 기능을 제공한다는 것을 알게 되었습니다. <br>
>> - 직접 구현하기 전, 관련 API를 먼저 확인하는 습관의 중요성을 다시 한 번 깨달았습니다.

### 입출력 요구 사항
입력
- 로또 구입 금액을 입력 받는다. 구입 금액은 1,000원 단위로 입력 받으며 1,000원으로 나누어 떨어지지 않는 경우 예외 처리한다.
```angular2html
14000
```
- 당첨 번호를 입력 받는다. 번호는 쉼표(,)를 기준으로 구분한다.
```angular2html
1,2,3,4,5,6
```
- 보너스 번호를 입력 받는다.
```angular2html
7
```
출력
- 발행한 로또 수량 및 번호를 출력한다. 로또 번호는 오름차순으로 정렬하여 보여준다.
```angular2html
8개를 구매했습니다.
[8, 21, 23, 41, 42, 43]
[3, 5, 11, 16, 32, 38]
[7, 11, 16, 35, 36, 44]
[1, 8, 11, 31, 41, 42]
[13, 14, 16, 38, 42, 45]
[7, 11, 30, 40, 42, 43]
[2, 13, 22, 32, 38, 45]
[1, 3, 5, 14, 22, 45]
```
- 당첨 내역을 출력한다.
```angular2html
3개 일치 (5,000원) - 1개
4개 일치 (50,000원) - 0개
5개 일치 (1,500,000원) - 0개
5개 일치, 보너스 볼 일치 (30,000,000원) - 0개
6개 일치 (2,000,000,000원) - 0개
```
- 수익률은 소수점 둘째 자리에서 반올림한다. (ex. 100.0%, 51.5%, 1,000,000.0%)
```angular2html
총 수익률은 62.5%입니다.
```
- 예외 상황 시 에러 문구를 출력해야 한다. 단, 에러 문구는 "[ERROR]"로 시작해야 한다.
```angular2html
[ERROR] 로또 번호는 1부터 45 사이의 숫자여야 합니다.
```
